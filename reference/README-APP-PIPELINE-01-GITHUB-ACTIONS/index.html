    GitHub Actions trong pipeline app — làm được gì, không làm được gì, tốn bao nhiêu¶

    GitHub Actions (máy ảo của GitHub tự chạy mỗi khi push) dùng để build + test + chụp màn hình app mà không cần mở Mac. Nó thay được bước 7 (app-run) một phần, không thay được bước 9–11 (ký, upload, nộp store).

    Cập nhật: 2026-10-04 · Workflow ở .github/workflows/. Luồng giao việc bằng điện thoại: README-APP-PIPELINE-02-PHONE-FLOW.md.

    1. Workflow đang có¶

    Workflow Chạy khi Làm gì Kết quả ở đâu
    pagecards-ios-build.yml push đụng apps/ACTIVE/xxx/ios/** · hoặc bấm tay build app iOS trên iPhone ảo (simulator) · chạy toàn bộ test · mở bản demo, chụp Home / My rooms / 1 room, sáng + tối dấu ✔/✘ ở tab Actions · ảnh ở nhánh ci-screenshots + mục Artifacts
    mac-apps-build.yml push đụng apps/ACTIVE/<slug>/mac/** (chỉ app vừa đổi) · bấm tay (gõ slug hoặc để trống = mọi app) swift build + swift test + mở .app chụp cửa sổ ✔/✘ ở Actions · ảnh ở ci-screenshots/<slug>/
    markdown-viewer-build.yml push đụng apps/ACTIVE/markdown-viewer/desktop/** · bấm tay build bộ cài Windows (.msi/.exe) + macOS (.dmg) Artifacts của lần chạy

    Chạy tay: GitHub → tab Actions → chọn workflow → Run workflow.

    2. Làm được trên GitHub Actions¶

    • Biên dịch app iOS / macOS / Windows trên máy ảo Mac (Xcode mới nhất) và Windows — không cần máy của mình.
    • Chạy test tự động (Swift Testing / XCTest, npm test). Dấu ✘ đỏ = code không build hoặc có test hỏng → không release.
    • Mở app trên iPhone ảo và chụp màn hình với dữ liệu demo (-demo -screen <tên>), cả chế độ sáng lẫn tối.
    • Đẩy ảnh chụp sang nhánh ci-screenshots (mỗi app một thư mục, chỉ giữ lần chạy mới nhất) để xem trên github.com hoặc để Claude tải về và tự nhìn ảnh.
    • Tạo bộ cài chưa ký (Markdown Viewer) để tải về thử.
    • Ghi lại lịch sử: mỗi lần push có một bản ghi build/test, biết commit nào làm hỏng.

    3. Không làm được (hoặc cố tình chưa làm)¶

    Việc Vì sao Ai làm
    Ký bản store (IPA/AAB) và upload TestFlight / Play cần chứng chỉ Apple Distribution, profile, key — đang nằm trên Mac của người dùng, chưa đưa lên GitHub người dùng chạy release.sh trên Mac
    Đăng nhập App Store Connect, điền thuế/ngân hàng, bấm Submit luật repo: Claude không đăng nhập store, không bấm Submit người dùng
    Chạy model Snap Words thật (ImageEncoder.mlpackage, ~93 MB) file không có trong git → CI build bỏ model và bỏ qua RealModelTests test trên Mac / iPhone
    Camera, tách sticker từ ảnh thật, phát âm iPhone ảo không có camera; tách sticker không chạy trên simulator iPhone thật
    Chọn ảnh từ thư viện, chia sẻ, kéo/xoay bằng 2 ngón cần người bấm; CI chỉ mở màn và chụp iPhone thật
    Thử mua in-app / RevenueCat sandbox cần tài khoản sandbox Apple iPhone thật
    Xem file trong Artifacts khi chưa đăng nhập GitHub GitHub chỉ cho tải khi đăng nhập dùng nhánh ci-screenshots

    Làm thêm được nếu sau này cần: ký + upload TestFlight ngay trên GitHub bằng cách cất chứng chỉ .p12, profile và App Store Connect API key vào Settings → Secrets. Đổi lại: chứng chỉ nằm trên máy GitHub (xem rủi ro §6). Chưa làm.

    4. Chi phí¶

    Repo app-AI-skills đang là private → tính phút máy ảo:

    Gói GitHub Phút miễn phí / tháng Phút macOS thực dùng được Ước số lần build xxx (~4 phút/lần)
    Free 2.000 ~200 (máy Mac tính ×10) ~50 lần
    Pro 3.000 ~300 ~75 lần
    Vượt mức — ~$0,062 / phút macOS ~$0,25 / lần build
    • Một lần build xxx đo được 3 phút 18 giây (2026-10-04); GitHub làm tròn lên theo phút.
    • Máy Windows tính ×2, Linux ×1. Ảnh/test report lưu trong Artifacts tính vào 500 MB (Free) — tự xoá sau 90 ngày.
    • Repo public thì máy chuẩn miễn phí, không giới hạn phút.
    • Giá lấy từ trang so sánh giá bên thứ ba (cicdcalculator.com, cicdcost.com), đọc ngày 2026-10-04 — kiểm lại ở GitHub → Settings → Billing and plans trước khi dựa vào.
    • Giữ chi phí thấp: workflow chỉ chạy khi đụng đúng thư mục app; hết phút miễn phí thì GitHub dừng chạy (không tự trừ tiền) trừ khi đã đặt hạn mức chi (spending limit) lớn hơn 0.

    5. Cái nào phải test bằng tay trước mỗi release¶

    CI xanh = code build được + logic đúng. Không có nghĩa là app dùng được trên máy thật. Trước khi upload TestFlight:

    1. Mở app trên iPhone thật (TestFlight) — không crash, dữ liệu cũ còn nguyên sau khi cập nhật.
    2. Chụp vài món đồ → tách sticker → đoán từ → lưu vào deck mới và vào deck có sẵn.
    3. Ngày dưới deck đúng ngày hôm nay (giờ Việt Nam).
    4. My room: mở xem, Edit, kéo/phóng/xoay, đổi sticker ⟳, Show words bật/tắt, ảnh nền từ Photos, chia sẻ ảnh.
    5. Chế độ tối + chữ cỡ lớn (Cài đặt → Màn hình & Độ sáng → Cỡ chữ).
    6. AppConfig.unlimitedScans — true chỉ cho bản TestFlight tự test; bản nộp store phải false (release.sh tự chặn nếu quên).

    6. Rủi ro và cách giảm¶

    Rủi ro Cách giảm
    CI xanh nhưng UI sai (chữ đè, nút mất) luôn xem ảnh ở ci-screenshots; Claude phải Read ảnh trước khi nói "chạy được"
    Bản CI khác bản thật (thiếu model 93 MB) RealModelTests chạy trên Mac trước mỗi release; ghi rõ trong log lần chạy
    Thêm field vào dữ liệu (SwiftData) làm hỏng dữ liệu cũ khi cập nhật chỉ thêm field có giá trị mặc định; thử cài đè bản mới lên bản cũ bằng TestFlight
    Xcode trên máy GitHub tự lên bản mới → build gãy dù code không đổi workflow in phiên bản Xcode ở đầu log; gãy thì ghim lại bản Xcode trước
    Lộ chứng chỉ / key nếu đưa lên Secrets hiện chưa đưa; nếu làm: dùng App Store Connect API key quyền thấp nhất, không bao giờ in ra log
    Hết phút miễn phí giữa tháng xem Billing; build tay ít lại; hoặc đổi repo public
    Nhánh ci-screenshots bị ghi đè mỗi lần chạy đúng thiết kế — mỗi app giữ ảnh mới nhất trong thư mục riêng, nhánh luôn chỉ 1 commit; ảnh cũ vẫn trong Artifacts 90 ngày

    7. Chỗ nối với pipeline 15 bước¶

    Bước Trên GitHub Actions Vẫn cần máy/người
    6 app-build build + test mỗi lần push —
    7 app-run chụp màn demo sáng/tối thử trên iPhone thật
    8 app-review bằng chứng test xanh + ảnh đọc code, Verdict PASS (người dùng)
    9 app-release — ký IPA bằng release.sh trên Mac
    10–11 listing / publish — upload, điền store, Submit (người dùng)
